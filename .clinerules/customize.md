# 커스터 마이징 원칙

## 소스 구조 변경 금지

소스 수정시 아래 내용을 반드시 숙지.
아래 내용에 위배 되거나, 의사 확인이 필요한 경우 반드시 사용자에서 물어본다.

1. 소스 수정시, 깃허브 오리지날 소스 (Clin) 과 upstream 구조가 깨지지 않도록 한다.
2. 커스텀 한 내용은 Cline 공식 소스에는 반영하지 않는다. (PR 안함)
3. 반대로 Cline 쪽 공식소스 변경, 추가시 내 소스에는 반영할 수 있도록 구성한다.
4. 깃 커밋, 푸시 로그는 한글로 작성한다.

## 한글화 및 브랜딩 원칙

소스 수정 중 아래 원칙에 따라 한글화, 리브랜딩이 안된 부분이 있으면 사용자에게 확인 요청할 것

1. 어플리케이션 이름은 "Gaea AI Pro" 로 한다.
2. 리브랜딩, 한글화 진행시 코드레벨은 절대 건드리지 말것 (코드명, 아이디명, 인덱스, enum, 클래스명, 인터페이스명, 변수명, 상수명, 문자열로 참조하는 레퍼런스 값, 경로명, 파일명, 디렉토리 명)
3. 수정 중 예외가 필요한 경우 반드시 사용자에게 확인 요청 할. ㅓㅅ
4. 한글화 최 우선 원칙은 사용자가 어플리케이션 UI/UX 를 통해 화면에 보여주는 부분에 한정한다. (예외가 필요한 경우 반드시 사용자 확인 요청할 것)
5. 직역보다 사용자 의도/맥락이 먼저
6. 용어 일관성 유지: 동일 기능은 동일 용어로 통일 (예: 워크스페이스, 체크포인트)
7. 명령/상태 문구는 짧고 명확하게
8. 코드/식별자/경로/명령어는 번역 금지
9. UI 가독성 우선: 길이 과도 증가, 어색한 존댓말/반말 혼용 방지
10. 브랜드 표기 일관성: 제품명/서비스명 표기 규칙 고정
11. 사용자 노출 텍스트만 변경: 내부 로직/식별자까지 무리하게 치환 금지
12. 핵심 자산 무결성 유지: 특히 codicon 경로/폰트(`codicon.ttf`) 훼손 금지
13. 링크/조직명/리포지토리 경로 변경 시 영향 범위 점검
14. 변경 후 전면 검색 검증: 잔존 구표기/혼합표기 남지 않게 점검
